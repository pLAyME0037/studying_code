# CLI

The command-line contract. Everything here was verified against
`build/bin/webc`, not read from the source alone.

```
Usage: ./build/bin/webc [command] [command-arguments]

Commands:
  ./build/bin/webc serve [port]
      Start up the Web Server. Default port is 8080.

  ./build/bin/webc dev [port]
      Run the server with auto rebuild + reload on source change

  ./build/bin/webc help [command]
      Show help messages for commands

  ./build/bin/webc version
      Show current version

The default command is `help`.
```

A bare `./build/bin/webc` prints exactly that and exits **0**.

## Commands

### `serve [port]`

Starts the coroutine HTTP server and blocks until killed.

```
$ ./build/bin/webc serve          # http://127.0.0.1:8080/
$ ./build/bin/webc serve 9000
Listening to http://127.0.0.1:9000/ (coroutine mode)
```

Before the socket opens it initialises TLS (if `WEBC_TLS_CERT`/`WEBC_TLS_KEY`
are set) and the **DB pool**, so a bad DSN or a bad certificate fails here, at
startup, rather than on the first request.

Startup always prints two lines regardless of configuration:

```
DB pool initialized with 8 connections
Listening to http://<addr>:<port>/ (coroutine mode)
```

The second says `https` when TLS is configured. If the pool cannot open, you
get an `ERROR:` first and **no** `DB pool initialized` line — see
[Known gaps](#known-gaps) below.

**Address is not configurable from the CLI.** It is the compile-time constant
`DEFAULT_SERVER_ADDRESS` (`src/webc.c:28`), currently `127.0.0.1`. The
commented-out alternative below it is `192.168.8.8`. To listen on other
interfaces you edit and rebuild, or put a reverse proxy in front.

### `dev [port]`

Watch sources, rebuild, restart. Prints on start:

```
dev: watching display/ core/ src/ css/ webc.c nob.c ...
dev: http://127.0.0.1:8080/ (Ctrl+C to stop)
dev: server up (pid 12345)
```

Polls once per second. The event vocabulary:

| Message | Meaning |
|---|---|
| `dev: server rebuilding...` | signature changed, `./build/bin/nob` is running |
| `dev: build successfully` | binary replaced, server relaunched |
| `dev: build failed waiting for the next change...` | **build broken, watcher keeps running** |
| `dev: server crashed (signal N)` | child died; relaunched next tick |
| `dev: port N is already in use by another process` | something else holds it |
| `dev: stopping; free the port and run 'dev' again` | follows the line above, once |

The important property: **a failed build never kills the watcher.** It clears
`dirty`, sleeps and keeps polling, so you fix the error and the next change
picks it up. A port conflict is warned about once (`warned`) rather than
spamming every second.

Stop with `Ctrl+C`.

The hash it watches (`dev_watch_signature`, `webc.c:64`) covers
`mtime ^ f(size)` per file under each root — cheap, no inotify, no dependency
graph. It deliberately skips generated/vendored paths so a rebuild does not
retrigger itself.

### `help [command]`

**Prefix matching** on command names:

```bash
webc help se        # → full description of serve
webc help serve     # → full description of serve
webc help nosuch    # → stderr: ERROR: unknown command `nosuch`;  exit 1
webc help ''        # → ambiguity: lists every command
```

Exactly one match prints the full description; several matches print them
all under `Commands matching prefix`; none is an error. No argument prints
the usage block.

### `version`

```
$ ./build/bin/webc version
WEBC BUILD TIME:   Thu, 15 Oct 2026 05:16:01 GMT
```

Prints to **stderr**. `WEBC_BUILD_TIME` is generated by the build into
`build/build_time.txt` → `build/bundle.h`, so it changes on every rebuild and
is also sent as the `Last-Modified` response header.

## Global flags

| Flag | Behaviour |
|---|---|
| `--help`, `-h` | equivalent to `help` (rewritten before dispatch) |
| anything else | must match a command name **exactly** |

Note the asymmetry: `help` matches by prefix, but the *dispatcher* does not —
`webc ser` is `ERROR: unknown command `ser``, exit 1. Prefix matching is a
feature of `help`, not of the command parser.

## Exit codes

| Code | When |
|---|---|
| 0 | command ran to completion; also `usage`, successful `help`, `version` |
| 1 | unknown command; missing `$HOME`; a command's `run()` returning false |
| 124 | (not webc) `timeout` killed it — `serve` and `dev` never exit on their own |

`serve` returns 0 only if `coroutine_server_run()` ever returns, which it
practically does not — a normal stop is `Ctrl+C`/`SIGTERM`.

## Environment

Set before dispatch, so they affect every command including `help`:

| Variable | Effect |
|---|---|
| `HOME` | **Required.** Missing → `ERROR: No $HOME environment variable is setup...`, exit 1 — before anything else runs. |
| `WEBC_DB` | Overrides the DB path; its parent becomes the "webc dir". |
| `WEBC_TRACE_MIGRATION_QUERIES` | Present → print each migration's SQL. Value is irrelevant; only presence matters. |
| `WEBC_TLS_CERT` / `WEBC_TLS_KEY` | PEM paths; must be set together. |

Unset, the DB is `~/.sqlite3/webc/db`.

## Known gaps

Verified defects in the CLI, kept here so nobody has to rediscover them.

### Port arguments are not validated

```c
if (argc > 0) port = atoi(shift(argv, argc));   // webc.c:215, :228
```

No `strtol`, no range check. Consequences:

| Invocation | Result |
|---|---|
| `webc serve notanumber` | `atoi` → **0**, binds an ephemeral port |
| `webc serve 70000` | `uint16_t` truncation → port **4464** |
| `webc serve 99999999` | wraps to a low port |
| `webc serve 8080 extra` | second argument silently ignored |

None of these error. Because `serve_run` binds whatever value it computed,
you can start a server on a port you did not ask for and not be told.

### `dev` watches two paths that no longer exist

The roots array (`webc.c:66`) is:

```c
"display", "src", "css", "js", "resource", "src/webc.c", "nob.c"
```

- **`core`** — deleted; `src/core/` is the real location now.
- **`nob.c`** — deleted; the build driver is `./nob.c` at the project
  root.

Missing entries are silently skipped (`get_file_type` returns neither
directory nor regular file), so `dev` still works — **but editing `nob.c` does
not trigger a rebuild.** Changes to the build rules require restarting `dev`
by hand.

Related staleness: `dev_visit_file` excludes
`module/sqlite-amalgamation-3460100/`, but the vendored directory is now
`third_party/sqlite-amalgamation-3460100/`. The exclusion no longer matches
anything, so touching vendored SQLite **would** retrigger a rebuild. The
`css/output.css` exclusion still works.

The startup message (`dev: watching display/ core/ src/ css/ webc.c nob.c ...`)
is a separate hardcoded string and does not reflect the array either.

### The database may be refused at startup

```
ERROR: /home/playme/.sqlite3/webc/db: Database scheme is too new. Contains
more migrations applied than expected. Update your application.
ERROR: Failed to initialize DB pool connection 0
Listening to http://127.0.0.1:8080/ (coroutine mode)
```

`db_pool_init()` stops at the first failed connection and returns **without**
setting `db_pool_initialized`, so `db_pool_get()` retries and fails on every
request. The server still listens: pages that need the database return 500.

This is the live state of this checkout — see
[dev-log.md](dev-log.md) for the analysis. The design decision behind the
error itself is D9 in [decisions.md](decisions.md).

## Recipes

```bash
./build.sh                                   # build
./build/bin/webc serve 9000                  # serve on a chosen port
./build/bin/webc dev 9000                    # watch + rebuild + restart
./build/bin/webc help se                     # prefix help
WEBC_DB=/tmp/x.db ./build/bin/webc serve     # private database
WEBC_TRACE_MIGRATION_QUERIES=1 ./build/bin/webc serve   # watch migrations
WEBC_TLS_CERT=c.pem WEBC_TLS_KEY=k.pem ./build/bin/webc serve   # https
SKIP_BUILD=1 ./test/run.sh                   # test the current binary
```
